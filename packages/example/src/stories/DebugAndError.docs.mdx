# 调试和错误信息

## 介绍

`debug` 是 `@event-chat/core` 默认提供的调试方法，用于开发者方便调试使用；这里为了符合实际开发的情况，使用 `@event-chat/antd-item` 做演示。

通过 `useEventChat` 返回的 `emit` 发起的更新，并在自身 `Hooks` 上配置 `debug` 调试日志。

当发送信息时，发送方可以接受到 3 类信息：

- `init`：发送方初始化后回调
- `emit`：仅在每次消息发送时回调，无论发送的消息最终是否会被接收
- `lost`：仅在发送消息遇到异常时回调，通常是路径解析异常

常用于主控方发送消息后，受控方没有正常响应时进行调试。因为在发送过程中，尤其 `@event-chat/antd-item` 这样的组件，开发者只能看到提供的路径名，而发送过程中提交的信息、计算的路径可以通过 `debug` 回调函数中获取并排查异常。

在 `emit` 类型的消息中，可以看到 4 个名称：

- `name`：接收的事件名；在发送方看到的是 `emit` 提供的 `name`，接收方通过 `callback` 拿到的是 `hooks` 配置的参数 `name`
- `origin`：发送方配置 `hooks` 时的名称，用于证明来源的事件名，不做路径转换
- `originName`：发送方 `emit` 提供的 `name`，不做路径转换
- `rule`：发送事件后根据 `name` 计算得到的路径，用于匹配接收方的事件名

接收消息的 `useEventCaht` 上通过 `debug` 方法获取调试日志，可以接受到 2 类信息：

- `init`：接收方初始化后回调
- `invalid`：已收到消息但不匹配接收规则，例如：组名、`schema`

> 若收到的信息匹配规则，会通过 `callback` 回调信息，不会触发 `debug`

常用于收到消息，但未触发 `callback` 时作为调试，可以通过 `debug` 获取不匹配的具体原因。

为了便于演示，这里直接通过 `@event-chat/core` 进行演示

通常验证发送消息的错误信息，通过 `zod` 在相应的 `schema` 中使用 `error` 去定义（`zod v3.0` 通过 `message` 定义）。除此之外还内置了 5 个错误信息：

- `customError`：自定义错误规则的错误信息，在接收方提供一个 `filter` 属性方法进行校验
- `groupEmpty`：非群组成员接收到来自群组成员的消息
- `groupProvider`：群组成员接收到来自非群组成员的消息
- `tokenEmpty`：非私信成员接受到私信
- `tokenProvider`：私信成员接受到非私信

> 这 5 个错误信息默认展示英文，为了便于查看错误信息允许通过属性 `lang` 自定义对应的信息

自定义方法 `filter` 接受一个回调参数，类型和 `callback` 基本一致 [[查看](/docs/document-eventchat--docs#callback回调函数)] ，回调参数 `detail` 来自 `emit` 传递的整个对象

```tsx
{
  filter?: (detail: Omit<EventDetailType<unknown>, 'detail'>) => boolean | PromiseLike<boolean>
}
```

回调参数对象中的属性 `detail` 为 `unknown`，是因为自定义校验方法会在数据校验前触发，此时还不清楚数据具体类型，可以自行通过 `schema` 判断数据类型。
