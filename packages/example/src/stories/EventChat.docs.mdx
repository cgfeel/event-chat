# `useEventChat`: 组件通信 `Hooks`

## 介绍

提供一个事件名和回调方法用于接收消息，同时返回一个 `emit` 用于向其事件名传递消息，无论组件层级都能传递信息，不会引发不必要的 `rerender`。

其中 `group` 和 `token` 将会根据接收消息的配置决定收到的值

- 接收消息没有配置 `group`，回调函数 `callback` 参数中的 `group` 为 `undefined`
- 接收消息 `token` 不为 `true`，回调函数 `callback` 参数中的 `token` 为 `undefined`

### `NamepathType`：事件名

类型如下，可以接受字符、数值、以及字符和数值的元祖、字符和数值的数组：

```ts
type NamepathType = number | string | Array<string | number> | Readonly<Array<string | number>>
```

可以定义为以下类型

- 字符：`pub-mox`
- `formily` 风格的 `namepath`，通过 `.` 划分结构：`pub.mox`
- `antd` 风格的 `namepath`，以数组划分结构：`['pub', 0, 'mox']`

当路径定义为数组类型时，会丢失原有的可读性，使用 `readonly` 作为元祖，可保持路径可读性。

> 字符类型的 `namepath` 和元祖类型可能不相等。例如：`['pub.mox', 0, 'name']` 和 `pub.mox.0.name` 得到的事件名不相等，前者会转换成 `pub.mox[0].name`

提供 `schema` 后 `callback` 回调参数对象中的属性 `detail`，会根据 `schema` 模型定义的规则推断数据类型。无论消息怎么发，最终收到的一定是约定好的类型。

### 异步消息

`Zod` 允许通过 `refine` 自定义校验规则，支持异步校验和同步校验异，当需要异步校验时，需配置入参对象的属性 `async` 为 `true`，例如：

```typescript
const { emit } = useEventChat('pub-mox', {
  async: true,
  schema: z.string().refine(async (id) => {
    // verify that ID exists in database
    return true
  }),
  callback: ({ detail }) => {
    // print id is string
    console.log('a----pub-mox', detail.id)
  },
})
```

### “公屏“喊话

组内的成员需要在 “公屏” 喊话，调用 `emit` 时设置属性 `global` 为 `true`，这样发送到群组内部的消息，同时会发送到“公屏“同名事件中，例如：

```typescript
useEventChat('pub-mox', {
  callback: (record) => {
    // receive.group is undefined
    console.log('a----pub-mox', record.group)
  },
})

const { emit } = useEventChat('sub-mox', {
  group: 'form-detail-edit',
})
emit({ global: true, name: 'pub-mox' })
```

由于“公屏“同名事件并没有提供 `group`，所以在回调参数的对象属性 `group` 为 `undefined`；除非将其设为组内成员，否则无法拿到 `group` 具体值。

> 不同组的同名事件无法通信，即便传递的消息设置 `group` 也不行；组内消息只能组内传递，或通过 `global` 同步发送给非组内的同名事件。

### 群组成员屏蔽“公屏“

当通过 `global` 向“公屏“发起喊话的同时，群组成员同名事件也会收到相同的消息。是否需要屏蔽群组成员接收来自“公屏“的喊话，这里交由业务来决定，例如：

```typescript
useEventChat('pub-mox', {
  group: 'edit-group',
  callback: ({ global }) => {
    if (!global) {
      // do somethine
    }
  },
})
```

### 同组件同事件名多群组

- 方式 1：一个组件中可以声明多个 `hooks` 来实现多个群组
- 方式 2：通过 `schema` 做区分

```typescript
useEventChat('multiple-event', {
  group: 'edit-group',
  schema: z.object({
    name: z.string(),
    type: z.enum(['color', 'size', 'byte']),
  }),
  callback: ({ detail }) => {
    if (detail.type === 'color') {
      // 1. manual checked
    }
  },
})

useEventChat('multiple-event', {
  group: 'edit-group',
  schema: z.object({
    name: z.string(),
    type: z.never(),
  }),
  callback: ({ detail }) => {
    // 2. auto checked by schema
  },
})

useEventChat('multiple-event', {
  group: 'other-group',
  schema: z.object({
    name: z.string(),
    type: z.enum(['color', 'size', 'byte']),
  }),
  callback: ({ detail }) => {
    // 3. auto checked by different group names
  },
})
```

## `token`：私信

调用 `useEventChat` 返回的对象属性中，包含一个 `token` 字符；当接收事件参数配置 `token` 为 `true`，将只接受 `emit` 时携带 `token` 字符和接收事件一致的消息。

> 私信发送允许和 `group` 一样通过 `global` 同时发送到 “公屏“，操作流程见 `group`

**携带 `token` 发送消息**

当 `emit` 发送消息携带了 `token` 但没有设置 `global` 的情况下，只能向 `token` 一致的事件发送消息。
